# 문서 기반 GraphRAG 설계 논의

## 구현된 것

문서 구조 기반 추출 초안, 예산 합계 검사, 전체 연결망, 예시 질문의 단계별 조회 경로. 현재 추출은 문서별 Python 규칙으로 수행했다. 모델을 이용한 자동 추출 결과가 아니다.

## 서로 다른 세 가지 보기

1. 조직·사업: 기관 → 부서 → 정책 → 단위사업 → 세부사업.
2. 예산 상세: 사업 → 연도별 예산 → 과목별 배정 → 산출내역.
3. 의미 분류: 사업 → 분야·지원 방식. 원문 사실과 구분되는 제안 분류.

세 개의 별도 DB가 아니라 같은 사업을 공유하는 관계와 보기다. 현재 전체 JSON에는 1·2만 반영했으며, 3은 단계별 화면의 설명용 예시다.

## 금액은 표로 관리하는 방향

사용자가 금액 노드의 효용에 의문을 제기했다. 금액 자체가 아닌 연도별 예산 기록을 노드로 만들었지만 연결망을 복잡하게 한다. 제안: 조직·정책·사업·분야는 그래프로, 연도·회계·예산과목·산출내역·금액은 표로 관리하고 사업 ID로 연결한다. 사업 선택 시 예산표를 표시한다. 현재 화면과 데이터는 아직 변환하지 않았다. 표는 UI 표현 또는 저장 모델 선택이며 반드시 별도 DB가 필요한 것은 아니다.

## 예상 질문 유형

조직 소관, 사업 계층, 예산 조회, 연도 비교·증감, 구성·비중, 조건 검색·순위, 전년 미편성, 정책 분야, 지원 대상·방식, 사업 공통점, 원문 근거·수치 검증, 종합 변화 요약. 신청 자격·성과·증감 원인·정책 추천에는 추가 자료와 판단 기준이 필요하다.

## 다양한 파일과 사용자 개입

확장자는 파서 선택의 단서다. 그래프 기준은 실제 표·서술 구조와 날짜·단위·식별 키를 보고 문서·구간별로 추천한다. 예산표는 계층+금액, 공고는 대상·자격·기간·절차, 회의록은 참석자·안건·결정·조치, 계약은 당사자·의무·조건·기한, 보고서는 주장·지표·관측·근거가 중심이다.

처리 순서: 파일 분석 → 기준 제안 → 작은 그래프·표 비교 → 기준 저장 → 전체 추출 → 코드 검증 → 오류 구간 재추출. 예상 질문을 미리 알지 못해도 진행할 수 있다. 사용자는 그래프/표 분리, 해석 분류, 문서 간 동일 사업 병합, 충돌 기록의 대표값 등 의미가 바뀌는 선택에 개입한다. 기존 기준은 재사용하고 새 구조·충돌이 있을 때만 다시 묻는다.

## 복수 문서

공통 조직·사업을 중심으로 출처별 기록을 연결한다. 예산안·확정예산·추경·집행액·결산액을 구분하고 발행일·연도·회계를 보존한다. 이름만으로 동일 사업을 병합하지 않고, 충돌 수치를 덮어쓰지 않는다.

## 모델 추출 품질

문서 분석과 추출을 분리한다. 승인 스키마를 고정하고 JSON Schema 출력, 문맥이 보존된 사업·표 단위 분할, 원문 근거, 좋은 예·예외 예시, 코드 기반 검산을 함께 사용한다. 모델의 확신 점수는 정확성 보장이 아니다. 사람이 검수한 표본에서 엔티티·관계 정확도/누락률, 금액·근거 정확도, 비용을 비교한다.

Together.ai 호출은 클라우드 추론이다. 로컬 배포 모델과 모델 계열을 공유할 수 있지만 실행 환경은 다르다. 지원 모델에서 구조화 출력 사용 가능 여부를 확인한다. 참고: https://docs.together.ai/docs/inference/chat/structured-outputs

## 미구현

Neo4j 적재, 임베딩·자유 질문 GraphRAG, Together.ai 호출, 자동 기준 추천·승인 UI, 금액표 분리, 안정적인 문서 간 ID·병합, 증분 갱신. 순차 ID는 이번 추출 안에서만 유효하다.
